## 存储、边界和恢复

模块化单体：FastAPI + SQLite WAL + 本地内容寻址仓库；React/TypeScript/Vite 前端由同一服务托管。所有项目、文件、审核和导出 API 从服务端会话取得租户；请求不能指定任意租户。PBKDF2 密码、哈希会话 token、HttpOnly/SameSite Cookie，八小时过期。跨站来源写请求拒绝。没有跨租户业务查询和公共原件链接。

本地初始化包含可重复使用的测试角色；实际成员应分别通过本地 CLI 设定密码。管理员可以维护编制数据，但不能替代专业复核账号。当前审核权限为项目所在租户内的 reviewer，尚无专业资质/项目分配细化授权。

所有修改通过 SQLite `BEGIN IMMEDIATE` 事务串行，避免更新丢失。报价保存输入副本与哈希，不通过后续对象引用重写历史。原始文件和导出文件按 SHA256 内容寻址。审计以每个项目独立的 previous_hash 链关联，普通应用接口没有修改/删除路径；触发器拒绝 SQL 普通更新与删除。

文档工作由进程内 BackgroundTasks 执行，任务状态持久化。进程重启时把残留 queued/running 标记为 failed 并说明中断原因，原件保留、允许重试。已完成任务再次调用解析不会重复生成证据。尚未达到独立可靠任务队列的进程隔离与吞吐要求。

## 审核与失效规则

编制对象保持 draft / approved / stale / rejected / needs_info / conflict；后端检查前置对象，不开放任意项目状态写入接口。业务流程覆盖 PRD 主状态中的受控子集，尚未实现所有中间状态与独立价格审定实体。

- 冲突事实须先拒绝不采纳候选，再通过选定值；不按出现次数投票。
- 每个参数和扣减量均须引用当前版本原件证据。没有结构模型就不支持精确钢筋量。
- 工程量生成要求全部构件尺寸已审核；清单生成要求当前算量已审核。
- 修改尺寸保留构件历史，使工程量、清单及报价审批失效；重算后旧计算书和清单移入历史，不再混入当前合计。
- 修改定额/价格后清单回到草稿，需要独立复核；缺少许可、版本或价格时停止计价。
- 规则包地区及当前有效期必须适用。项目历史计价日期选择尚未实现，不能用于直接重建历史结算标准适用性。
- 报告审核同时检查范围资料、事实、构件、算量、清单、规则、价格及快照有效性。范围外资料明确显示缺项；审核成果只代表所选试点范围。
- 已生成的导出件单独留存；审批失效只影响新导出的状态，不修改过去的字节。
