# 0.8 报价版本差异归因与对账留档

本版细化 PRD F11/F12 的报价版本差异：按不可变报价快照拆分金额变化，检查差额闭合并留存独立对账单，不重算或覆盖历史报价。

## 使用方式

在取费汇总页打开“报价版本差异”，选择两个报价版本并对比。查看量价等分类合计、逐条清单及资源变化、逐项费用；可点击“下载并留档对账单 JSON”。成果交付页的历史导出件会标记“版本对账单”，支持已有文件下载及哈希核查。

## 对账口径

- 按清单ID关联。相同单位、编码和项目特征时，先以原单价计算数量变化，再以新数量计算单价变化：数量影响=`(新数量−原数量)×原单价`；单价影响=`新数量×(新单价−原单价)`。各项修约至分，剩余合价差额列作修约余额，避免把尾差隐藏到其他项。
- 新增、移除清单分别单列。单位、编码或项目特征变化时，保守地将全额差额列入计量口径变化，不能仅凭软件字段判定它仍是同一计量对象。
- 名称、工程层级及定额/资源变化也会显示，即使金额不变。定额及资源按原始顺序位置展示前后值、价格、消耗、来源和变化字段，不按相似名称推断它们相同。
- 费用按原计算顺序位置逐项展示前后基数、费率、金额及差额，同名费用不合并；位置或名称变化不被解释成专业意义上的同一费用。
- 使用80位Decimal上下文，核查两版快照哈希及输入哈希、各版分项/费用/总价闭合。各类清单影响合计必须等于分部分项差额，分部分项差额加费用差额必须等于总价差额，否则拒绝出具对账结果。
- 标明规则、计价日期及专业范围是否变化，显示历史报价失效标记。对账是指定计算顺序下的会计拆分，不是自动专业因果结论，也不恢复审批或批准任一报价。

## 留档与边界

对账单包含左右版本ID、原报价哈希、完整前后清单数据、资源/费用明细及对账内容哈希。导出时重新检查左右版本及对账内容校验值，文件以SHA256留存并写入项目审计；后续输入变更不重写旧对账件。接口继续按企业/项目作用域鉴权。对账单独立于报价成果，不标为审核报价。

当前提供JSON留档，未提供独立差异PDF/Excel表式。算法不猜测拆并清单间的语义对应，也不能自动判断工法、材质、合同或计量规则变化的专业因果。价格合法性、计量口径和专业结论仍须人工核查。

## 验证

101项自动测试通过，前端类型检查及生产构建通过。新增覆盖量价同时变化、修约余额、增加/移除、单位/特征变化、仅改名、同名费用与顺序变化、超过默认Decimal精度的大金额、快照异常/不闭合/非有限数字、租户限制、留档校验值、历史文件不变及不修改审批。
