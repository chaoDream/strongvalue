# 0.48 供应商报价修订与重新询价

补齐F07价格来源失效后的恢复流程。已采用报价被撤回、撤审或失效时，编制人可以明确撤出当前资源价格，填写原因并关联原始依据，重新进入待询价。供应商的新报价通过修订链追加，经独立复核及再次明确采用后补价，清单仍须重新送审。

## 撤出当前价格并重新询价

在供应商报价列表中，只对当前资源仍使用的采用记录显示“撤出价格并重新询价”。提交须包含报价、清单和资源的读取校验值、非空原因、原始依据，以及严格布尔确认。服务器在同一事务内检查当前采用关联和原资源版本，验证新依据的证据哈希及原件实际字节。

操作撤出单价、价格来源、许可、期次、税制及有效期等旧价格元数据，资源明确变为`unpriced`、价格为空，重新产生待询价任务；保留当前资源规格、费用归属、消耗量、定额系数和清单数量。清单退回待复核，当前报价审批失效。不会填入零价、生成虚假差额，或撤销/覆盖原报价、原采用记录及历史计算结果。

重新询价记录保存原价格、采用记录、操作前后资源、版本、原因、人员时间、新依据及哈希。界面可展开历史并打开依据。原报价已撤审或其旧原件缺失时，仍允许使用新的有效依据恢复；新依据失效或重新询价记录变化后，阻断后续新报价采用和新的计价。

同一请求支持幂等重试，复用请求标识更换内容被拒绝。历史采用、已改用其他价格的资源、未采用报价不能撤出当前价格；并发修改或来源损坏时不留下部分变更。

## 报价按版本追加修订

资源待询价时，可对最新报价登记修订。修订限同一供应商、同一具体资源和规格，不能把其他供应商或规格混入同一修订链。界面保留供应商、规格和条件供核对，要求重新填写报价单、单价、有效期、原始依据及核对原因。其他供应商或不同规格应另行登记。

新报价保存系列ID、修订序号、前一报价及当时哈希，保持待复核，不继承旧审批、不自动补价。修订链只允许从最新版本继续追加，防止并发产生分叉。旧报价内容、原审核和采用记录不改写，列表明确标为历史修订，禁止用于新的审定或采用。拒绝新修订也不会自动恢复旧版本。

旧版登记按R1兼容读取，既有请求标识的幂等行为保持；新修订可继续从旧记录追加。新报价经独立reviewer核查后，由编制人再次确认规格、税制、许可、供货条件和选择依据，再补入价格。恢复后的资源和清单继续接受既有审定、来源、有效期和确定性计价门禁。

## 历史依赖与导出

重新询价不等同于撤销原报价审批；旧审批作为历史记录保留，新报价必须重新复核。修订采用后，再拒绝或要求补充未被当前资源使用的旧报价，不使新价格和新报价版本失效；当前正在使用的报价撤审仍会阻断清单和后续计价。

报价快照新增重新询价记录。JSON、Excel、PDF增加“供应商报价修订”和“供应商重新询价”台账，结合已有登记、采用及审核台账追溯全过程。后续修订或重新询价不混入旧快照，也不改变已生成文件。

主要接口：`POST /api/v1/projects/{pid}/supplier-quotes/{qid}/reopen-inquiry`；原登记接口增加可选`revision_of`及`revision_hash`（须同时提供）。列表返回最新修订标记、当前可重新询价目标的校验值及是否可继续修订。所有接口继续检查项目成员、编制/复核角色和租户隔离。
