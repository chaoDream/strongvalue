# 0.5 完整交付证据包与文件校验

本版补充 PRD 的“成套报表及审计证据包”交付链：选定版本的原件、结构化快照和报表可以一起下载，并在本地独立校验。此功能不代表真实工程专业验收。

## 操作

1. 在成果交付页选择报价版本，点击“检查选定版本证据”。系统核对报价/输入快照哈希、原件内容/登记大小、证据与文档版本关联、项目审计链，并显示资料数量、大小、事件数量及业务状态。
2. 选择企业报表样式后，点击“完整交付证据包”。ZIP包含同一选定版本的PDF、Excel、JSON成果，以及报价快照、原件索引、原始文件、打包前本项目审计链、校验结果、逐文件SHA256清单、说明与离线校验工具。没有报价时生成明确标识的无价草稿包。
3. 在历史文件完整性核查中选择已留存的ZIP、PDF、Excel或JSON，查看实际SHA256与留档SHA256是否一致。文件损坏或缺失时显示失败，历史下载接口也会拒绝下载。
4. 如需离线核查，将包内的 `verify_delivery.py` 保存到本地，使用Python 3执行 `python verify_delivery.py 证据包.zip`。只需标准库，不依赖项目环境；输出JSON和退出码（0通过、1失败、2用法错误）。校验时不会解压或执行其余包内文件。

## 数据与状态

- 有报价时仅从选定报价快照选取原件，后来新上传的资料不混入旧版交付；相同原件按内容哈希去重，原文件名保存在索引中，不用原文件名作为ZIP路径。审计链截至打包前，明确包含报价生成后的修改或撤审事件。
- 原件缺失/损坏、快照哈希异常、证据关联不一致、日志链异常或大小超限时，阻断ZIP生成，不新增导出件或成功事件。打包过程中再次检查原件，防止检查与读取之间的变化。
- 文件一致性检查通过并不绕过业务审核。待审输入、来源失效或历史报价失效时可以交付草稿包，所有报表及清单均保留草稿状态；旧包的字节和原导出状态不因后续变更而重写。
- 离线工具核查精确文件集合、逐文件大小/哈希、原件索引、报价及输入快照、审计链，拒绝额外/缺失/重复文件和不安全路径。
- 原件去重后最多100MB、最多1000份文档；整包内容另设大小上限。当前同步打包会读取所选版本全部原件并生成PDF/Excel，适用于本地小规模交付，不是生产异步任务队列。
- 原件、审核意见及日志可能含非公开工程信息，须按项目保密范围交付。接口继续按项目租户鉴权，不包含账号、会话、密钥或其他企业日志。历史迁移快照保持原状。

## 验证

82项自动测试通过，前端类型检查及生产构建通过。新增覆盖审核/草稿/无价包、企业模板、同版本原件和原件去重、来源更新后旧包不变、跨企业/跨项目拒绝、缺失/损坏/打包期间变化回滚、快照及审计链异常、大小限制、历史文件损坏拒绝、离线恶意路径/重复/额外/缺失文件和独立进程运行校验工具。

浏览器在独立合成工作区实际完成：选定版本检查、ZIP下载留档、历史ZIP哈希核查。截图为 `qa/v0.5-delivery-check.png`、`qa/v0.5-artifact-verify.png`；未向实际工程写入测试业务数据。

## 尚未完成

SHA256清单及日志链只验证一致性，不是可信数字签名，不能证明来源真实性、抵御整体重制或代替专业签审；外部可信时间戳、WORM存储及签名证书流程未实现。完整性核查也不能识别尚未上传的图纸或判断专业资料是否真实充分。
