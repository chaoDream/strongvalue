# 0.40 图纸目录、平立剖互参与修订复核

补齐PRD F04中可由原始依据与人工复核实现的图纸身份和跨图索引流程。在“项目与资料”增加图纸目录，支持平面、立面、剖面、详图、系统图及其他图纸。此功能记录经人工核对的关联，不识别任意构件边界、不推算缺失尺寸、不用PDF像素计算工程量。

## 图纸身份与原件位置

编制人明确填写图号、图名、专业、图纸版次及登记依据，并选择当前原件、实际PDF页码和原文摘录。图纸版次与系统上传V版本、登记R修订分别保存，不从文件名自动决定版次。PDF页码须与证据一致且不超过实际原件页数；CAD/BIM可用人工证据登记，固定PDF页码留空，不宣称已有授权解析器。

登记保存文件哈希、证据哈希、摘录、作者、时间及原因。创建与复核均读取实际原件核验哈希；已替代文件、跨文件/跨页证据、不存在的原文和非法视图被拒绝。支持的原件为PDF、DXF、DWG、IFC，合同等其他资料仍走工程事实。

同项目同专业同图号的多个当前登记形成冲突分组。图号用Unicode兼容字符、大小写及空白归一比较；不因版本文字、文件名或出现次数选择正确图纸。独立复核人须先拒绝不采纳候选，再审定保留登记。不同专业分别核对。

## 平立剖互参

两端图纸须先复核通过且没有来源问题。编制人选择起点、目标、所核对的构件或部位、索引类型及原图标记；剖面、立面、详图索引须与目标视图一致，专业互参由人工明确说明范围。标记须实际出现在起点图纸所选页的摘录中。

互参绑定两端具体登记ID、对象哈希与独立复核记录；不能指向自己、其他项目图纸、历史修订或未审图纸。图纸重新审批即使内容相同，也须重新核对互参。互参不自动建立算量参数依赖，不向现有构件、工程量或清单写入推测值。

## 不覆盖历史的修订与门禁

- 图纸和互参修订须提交读取时对象哈希，追加同一序列的新R记录，保留旧记录及原审批。不能修订或重新审批历史R版本；批量复核只推荐当前候选，整批仍具有事务原子性。
- 新修订不会自动继承审批或把旧互参改指新图。图纸登记变更使现有构件、算量、清单及报价需重新复核；互参变更使报价失效。审批拒绝/补件也会触发相应下游失效。
- 当前未审登记、同图号冲突及失效互参阻断新的报价与成果审批。没有登记台账的既有项目保持原流程；不需要的当前登记和互参可由独立复核人拒绝并留存原因，拒绝新修订不会自动重新启用旧版本。
- 列表分别显示原审批与当前有效性。已审互参所指图纸改版后显示“原审定已失效，须重新核对”，旧记录不被覆写；可展开查看具体待办及历次修订。
- 租户、项目成员、编制/复核角色继续由服务端校验；管理员及编制人不能代审。所有创建、修订和审核保留审计事件。

## 快照与交付

报价快照增加图纸登记和互参记录。PDF、Excel、JSON增加“图纸目录与版次”和“平立剖图纸互参”表，保留当时报价所引用的具体登记版本、当前/历史范围、审核状态、原文及依据。新登记不会混入旧报价导出；原留档文件不修改。未计价草稿另列当前“图纸校核待办”，不掩盖失效关联。

新增接口：`POST /api/v1/projects/{pid}/drawing-sheets`、`POST /drawing-sheets/{sid}/revisions`、`POST /drawing-references`、`POST /drawing-references/{rid}/revisions`（后三条同属项目路径）。项目详情的`drawing_register`返回当前ID、冲突、逐记录来源问题、校核待办及视图/索引目录。独立审核沿用`reviews`与`reviews/batch`，类型为`drawing_sheets`和`drawing_references`。
