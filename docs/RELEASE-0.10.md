# 0.10 项目时间与计价日期专业裁决

本版补齐 PRD 7.3 时间策略中可独立实施的登记、证据和专业裁决流程，连接 F08 计价适用性、F09 交付与 F11 版本审核。原有单一手工计价日期仍兼容，不将历史项目自动认定为已完成专业日期裁决。

## 已实现

- 在取费汇总或系统配置中登记招标、合同签订、设计版次、施工、结算时间；仅登记实际有依据的节点，至少一个。设计节点须填写版次说明，各节点分别关联当前原件证据。
- 明确选择已登记节点的日期，或填入合同另行约定的计价日期；选择理由、合同约定、不同日期的裁决说明和来源均必填。不按最早、最晚或多数日期自动推断法律适用。
- 编制账号提交版本，提交时使旧报价审批失效；独立复核账号查看节点、说明、原文和来源，通过审核后原子应用日期。最新裁决待审、退回、拒绝或来源失效均阻断新计价及成果审批。历史版本保留，只能审核最新裁决；提交和审核均使用对象哈希防止覆盖已变化内容。
- 原件须存在且内容SHA256一致；已替代来源不能继续通过复核或支持计价。后续直接修改手工日期使已有裁决失效，即使改回原日期也须重新复核，不能借设置接口恢复审批。
- 日期审定不自动替换规则包或价格。历史日期不在当前规则有效期内仍阻断计价，须另行配置和复核实际适用规则；价格有效性继续按同一计价日期检查。
- 报价快照保存当时的全部日期裁决记录、节点、来源、审核及计价日期；Excel/PDF通用封面说明展示节点、设计版次、裁决理由及证据编号。后续日期变化不改写旧报价及其报表日期。无价交付证据包也包含日期记录。
- 未登记裁决的兼容项目继续使用原手工日期或当前日期，同时在新报价警示与报表中明确尚无多时间节点专业裁决。

## 操作

上传含日期及适用约定的实际原件后，在“取费汇总 → 项目时间与计价日期裁决”提交；reviewer账号打开“日期复核 / 审核记录”，核对原文与不同日期的业务含义后决定。审定后配置在该日期适用的规则和价格，再生成新的报价快照。提交更新裁决时保留旧版本及审计。

## 验证与限制

120项自动测试通过，前端类型检查与生产构建通过。新增13个测试用例覆盖非法或非规范日期、节点缺失、设计版次必填、跨租户与角色隔离、重复提交与过期对象哈希、历史版本不可复核、批量目标过滤、另行约定日期、手工修改后的重新审定、来源替代/缺失/损坏、历史日期规则阻断、报价与报表快照不变。

独立合成工作区通过浏览器实际登记招标和合同日期、选择招标日、填写原文依据和裁决说明；确认未审定时计价被阻断，再切换复核账号审定并看到日期应用。截图 `qa/v0.10-pricing-basis.png`。没有修改实际工程资料，没有真实专业适用性签审。

本版不自动识别合同法律效果、不自动解决多合同/多阶段规则冲突，也不引入官方标准数据库。节点真实性、证据内容是否充分、计价场景及具体标准适用仍由有权专业人员核查。未登记节点显示为未录入，不代表该业务事件不存在。兼容日期模式尚未全局强制迁移为新流程。

复杂识图、比例标定、全专业自动算量、授权定额和价格数据、专业软件往返、项目级细分权限、独立可靠任务队列和生产基础设施、真实工程黄金底稿验收仍未完成，不能将PRD标记全量完成。
