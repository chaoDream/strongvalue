# 0.13 项目成员与访问范围

本版补齐PRD用户角色、F11/F12及安全要求中项目级成员分配的基础能力。在原有企业隔离之内，增加按项目限制访问的可选名单；组织角色继续决定谁能编制和谁能签署复核。

## 已实现

- 系统配置页显示项目访问范围，支持“企业内共享”或“仅指定成员及本企业管理员”。旧项目和新建项目均默认兼容企业共享模式，不在升级时静默收回权限；受限模式由管理员主动开启。
- 企业管理员可以切换共享范围、指定或移除本企业启用成员，空名单表示仅管理员可访问。已列入受限项目的manager可维护名单，但不能切换共享范围，也不能将自己移出导致失去管理入口。其他角色不能维护名单。
- 名单只缩小项目访问范围，不改变组织角色：列入名单的estimator仍不能签署复核，reviewer仍不能修改编制数据；管理员仍不能代替独立reviewer签审。跨企业访问继续拒绝。
- 项目列表过滤非成员项目；项目读取、原件、报价、审核对象、审计、历史导出文件、交付检查及各业务接口统一通过项目访问检查。已登录的旧会话在后续请求中重新检查当前名单，不依赖前端隐藏按钮。
- 范围修改使用对象哈希与版本校验，拒绝覆盖并发变化；名单拒绝重复、外企业、不存在或停用账号，最多200个指定成员。变更原因必填，保留前后范围与操作者审计。
- 同企业非成员直接访问受限项目时返回与未知项目一致的404提示，并在受限项目审计中保留拒绝事件、操作者及请求路径。拒绝日志在业务事务结束后独立写入，避免随业务异常回滚；审计沿用原哈希链及不可普通更新/删除机制。
- 企业价格库过滤无权访问来源项目的条目，包括检索数量、项目名称、价格摘录和原件链接；知道条目编号也不能借复核或采用接口读取受限来源。
- 受限项目不再作为企业共享价格或原件来源，成员也不能发布或新采用其企业库价格。已有来源转为受限后，依赖该来源的企业库价格在新计价中不可用，目标项目可见阻断原因；管理员恢复企业共享后，仍满足原审批/来源条件的条目可继续使用。
- 名单变更不改写工程量、既有审核、历史报价或历史导出件。先前已合法复制到其他项目的资料和已经下载的文件保留，不能通过调整名单追回。
- 已经合法提交的解析是服务端任务，不依赖发起人后续的项目成员身份继续持久化结果；本地和模型任务内部仍按原企业、文件、任务执行标识、来源及模型确认指纹检查。请求端的查看、上传、重试或新模型发起仍须通过当前项目访问检查。名单不是任务取消或外发授权撤销接口。

## 操作

以企业管理员登录“系统配置与审计 → 项目成员与访问范围”，选择受限模式，勾选确需访问的编制、复核或负责人账号并填写原因。管理员始终可以访问本企业项目，不必把自己放入名单。设置生效后，非成员的后续项目请求会被拒绝；已有浏览器显示内容需刷新，不尝试清除之前已获取的副本。

组织账号停用仍立即注销会话；重新启用账号后，原项目名单中的授权仍可能生效，应一并核查名单。尚未启用受限模式的项目仍是企业共享，不能声称全部项目已默认按最小成员隔离。

## 验证

168项自动测试通过，TypeScript检查和生产构建通过。新增10个用例覆盖列表过滤、原件/报价/审核/历史导出/交付检查访问拒绝及审计、旧Cookie后续请求重新检查、项目之间不互相锁定、组织角色不提升、管理员与负责人边界、自己移出保护、哈希冲突、非法/外企业/停用成员、历史业务和导出字节不变、受限后后台解析完成、企业库隐藏/阻断及先前复制资料保留。

浏览器在独立合成工作区实际将企业共享项目收窄为estimator、reviewer两名指定成员，确认名单和变更日志；切换未分配的test_manager后，项目选择器只剩另一个企业共享对照项目。截图 `qa/v0.13-project-access.png`。没有改变实际工程的权限或数据。

## 边界与剩余范围

本版是项目成员范围与已有组织角色的组合，尚无专业资质验证、分专业签审、按文件单独授权、临时到期权限或完整商业IAM。成员仍能保存其已获准读取的内容；已经外发、下载或复制的资料不能远程收回。日志仍属于本地数据库审计，不代表外部WORM防护或专业安全验收。

复杂识图、比例校准、全专业算量、官方授权价格/定额、专业软件往返、独立可靠任务队列及生产基础设施、真实工程黄金底稿验收仍未完成。PRD不能标记全量完成。
