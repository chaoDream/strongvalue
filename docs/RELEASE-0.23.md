# 0.23 专业软件往返验证台账

继续补齐PRD F10及10.2–10.3的试验记录和字段损失对照。系统配置页可登记指定软件版本、适配或人工整理工具版本、源/回导格式、许可条件、执行依据、模型与费用保真说明、失败恢复和回退方案，并对人工整理的两份字段表执行确定性比较。

本版没有调用GTJ/GQI/GCCP，没有获得厂商接口或执行真实授权软件往返。台账审定只表示列示试验记录经独立人员核查，不启用任何厂商接口，不证明原生模型或全部费用对象无损，也不替代工程报价成果审批。

## 使用流程

1. 在“系统配置与审计→专业软件往返验证台账”下载字段对照模板。基准与回导表均使用XLSX，指定工作表为“字段对照”；其他页用于说明。
2. 在合法授权的同版本软件中执行实际导出、系统或人工中间整理、输出、软件回导；按实际导出内容填写两份字段表，保留源软件文件及运行日志。字段整理本身不属于自动适配器。
3. 将基准表、回导表、许可及运行依据上传到项目资料。新建试验，登记软件完整版本、授权范围、试验日期、实际回导成功/失败、保真说明和回退处理。
4. 预览逐字段对照，确认后保存为待复核记录。独立reviewer核对文件及记录；有差异或回导失败的事实记录仍可复核，但字段对照结论保持失败。
5. 需要重试或修订时建立同组新版。旧版保留查阅，新版重新复核；不能恢复旧版当前效力。可单独导出JSON/Excel并从历史导出件下载原留档文件。

## 对照口径

模板列为：`对象类型,对象标识,字段,值,单位,比较方式,绝对容差`。

- 对象类型、对象标识、字段组成唯一键，重复键拒绝。请将构件、工程层级、清单、子目、资源、换算、措施及税费需要核验的字段明确列示；不支持的字段也须保留在基准中。
- 基准逐行指定“文本”或“数值”。文本保留空格、大小写和空值差异；数值使用Decimal，支持正负数、最多18位有效数字/18位小数，绝对值不超过1e18。基准数值须显式填写非负绝对容差，无容差填0。
- 返回表的比较方式和容差不参与判断，防止用返回文件放宽基准口径。单位必须一致，系统不隐式换算。
- 分别列示一致、容差内差异、值变化、字段丢失、单位变化和新增字段；非数值返回不能被当成零。软件实际回导失败时不能给出对照通过，可不提供回导表，基准字段均列为未返回。
- 覆盖率仅为列示基准字段的同标识匹配率，包含值或单位变化的匹配字段；同时展示独立差异计数，不能把匹配率解读为兼容率或软件完整字段覆盖率。
- 每份字段表最多5000条明细，严格校验7列表头、重复标识、空表、精度、容差及文件内容；拒绝公式、错误单元格、多余列和不支持的格式，不执行来源公式或宏。

## 审核、版本与留档

- 预览无写入。保存重新读取原件，绑定软件/试验元数据、逐字段结果和依据内容，拒绝过期预览。请求幂等，同组新版携带上一记录哈希；失败不部分写入。
- 使用现有租户、项目成员和编制/复核权限。管理员和编制人不能代审。审批核对内容哈希、文件与依据版本、实际原件字节，并重算比较结果。
- 状态页重新检查来源与原件；来源被替代、缺失、篡改或摘录改变时显示失效。历史版本不能重新审批为当前有效试验。
- JSON/Excel包含试验说明、完整字段对照、文件哈希、许可/运行证据和审核意见；Excel防止公式注入。导出依据当前有效性显示已复核或草稿，撤审、来源失效或新增版本后不再生成有效审核标识。
- 留档使用现有哈希校验及项目权限，并以`integration_trial`区分用途；历史文件字节不随撤审改变。试验新建、批准或拒绝都不修改工程量、价格、规则、报价快照或报价成果审批。

## API与验证

- `GET /projects/{pid}/integration-trials/template`：空白字段表模板。
- `POST /projects/{pid}/integration-trials/preview`、`POST /projects/{pid}/integration-trials`：预览与提交。
- `GET /projects/{pid}/integration-trials/status`：记录、当前来源与复核状态。
- `GET /projects/{pid}/integration-trials/{id}/exports?format=json|xlsx`：单独留档，沿用项目历史文件接口校验下载。
- 审核集合为`integration_trials`。现有`/integrations/capabilities`保持GTJ/GQI/GCCP未配置、未验证，`can_import/can_export`均为false。
